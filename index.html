What it is ​

Sepia is the agent-session abstraction: one canonical session IR, per-agent store drivers speaking ndjson JSON-RPC, an ACP client for every coding agent, and sepia serve — the stdio service orchestrators embed.

Why ​

Every coding agent keeps sessions its own way — SQLite, JSONL, directory layouts. Sepia maps them all onto one IR so listing, exporting, converting, and driving sessions is agent-agnostic, and keeps the mechanism stable enough that peregrin can build policy on top without linking internals.

Boundary ​

  • Owns: session mechanism — the IR, store drivers, attach, prompt, restore/rewind, agent configs, sepia serve.
  • Doesn't own: orchestration policy (peregrin), distribution (tamias), surfaces (pavo).
